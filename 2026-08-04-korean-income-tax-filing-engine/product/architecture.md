# 아키텍처

## 경계

```text
호출 시스템의 정규화 입력
        ↓
TaxCase 검증 ── 미지원 → 수동검토 큐
        ↓
연도별 Ruleset → 계산 커널 → CalculationResult
                                  ↓
                         canonical payload
                                  ↓
                  승인된 NTS 파일 스키마 어댑터
                                  ↓
                    변환검증 대상 바이트 파일
```

계산 커널은 주민등록번호, 이름, 계좌번호를 요구하지 않는다. `taxpayer_ref`는 호출 시스템 내부의 비식별 참조키만 허용하는 계약이다. 실제 신고 식별정보 결합은 제출 경계의 별도 보안 모듈 책임으로 둔다.

## 설계 판단

- **원 단위 정수:** `float` 반올림 오차를 배제한다.
- **실패 차단:** 미지원 연도·소득·해외요소·결손금은 계산하지 않는다.
- **파라미터 외부화:** 세율/근로소득공제를 JSON으로 분리하여 변경 diff를 작게 만든다.
- **경비율 이중 잠금:** 업종코드, 경비율 값, 적용자격 확인이 모두 있어야 단순경비율 경로를 탄다.
- **파일 규격 이중 잠금:** `reviewed=True`인 명시적 스키마 없이는 바이트를 만들지 않는다.
- **국세/지방세 분리:** 3.3% 중 국세 3%만 국세 기납부세액에 합산하고 0.3%는 별도 출력한다.

## 규칙 변경 절차

1. 공식 문서의 발행기관, 제목, 게시일, 적용 귀속연도, 파일 해시를 기록한다.
2. 새 연도 규칙 파일을 추가하고 기존 파일을 수정하지 않는다.
3. 경계값 테스트와 전년도 회귀 테스트를 함께 실행한다.
4. 세무 담당자가 계산표를, 개발 담당자가 스키마/인코딩을 각각 승인한다.
5. 운영 호출자는 승인된 규칙 버전을 명시적으로 허용 목록에 올린다.

## Maintenance harness

`krtax.maintenance`는 세 층의 게이트를 제공한다.

- 출처 게이트: 공식 HTTPS 도메인 허용목록, 문서 식별 마커, 정규화 본문 지문
- 규칙 게이트: 구간 정렬, 열린 마지막 구간, 누진공제·근로소득공제 연속성
- 승인 게이트: 운영 기준 규칙 파일의 SHA-256 해시 고정

온라인 확인은 명시적 `--online`에서만 수행하고 기준선을 자동 갱신하지 않는다. 사이트 변경과 정책 변경을 분리하여 레이아웃 변경이 세법 자동 반영으로 이어지지 않게 한다.
