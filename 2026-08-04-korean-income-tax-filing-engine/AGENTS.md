# AGENTS.md

## 목적과 적용 범위

이 파일은 이 프로젝트 폴더 이하의 모든 작업에 적용된다. 프로젝트의 목적은 대한민국 종합소득세 계산과 전자신고 변환 로직을 안전하게 유지하는 것이다. 운영 정확성, 근거 추적성, 개인정보 보호가 개발 속도보다 우선한다.

## 기밀 유지

- 이 폴더의 요구사항, 고객 식별정보, 비공개 전자신고 규격, 운영 데이터는 외부 AI·검색·이슈·로그로 전송하지 않는다.
- 웹 조사는 일반화된 세법 용어로 하고 `maintenance/source-registry.json`에 등록된 공개 공식 출처를 우선한다.
- 테스트 데이터는 합성값을 기본으로 한다. 고객 자료는 `private/` 또는 `fixtures/client/`에만 두며 Git에 포함하지 않는다.
- 계산 커널에는 주민등록번호, 이름, 계좌번호를 전달하지 않는다.

## 라이선스와 권리 출처

- 프로젝트 공개 가능 부분은 Apache License 2.0(`Apache-2.0`)을 사용한다. `LICENSE` 공식 영문 원문을 수정하지 않는다.
- 새 코드·문서·데이터는 기여자가 Apache-2.0으로 제출할 권리를 보유하는지 확인한다. 외부 기여에는 `CONTRIBUTING.md`의 DCO sign-off를 요구한다.
- 제3자 구성요소를 추가하기 전에 라이선스 호환성, 저작권 고지, NOTICE 의무를 기록한다. 출처나 권리가 불명확하면 포함하지 않는다.
- 고객 데이터, 원 발주자료, 비공개 전자신고 규격과 영업비밀은 Apache-2.0 배포 대상이 아니다.
- 라이선스는 세무서비스 운영 책임, 개인정보 의무 또는 전자신고 권한을 해결하지 않으므로 `DISCLAIMER.md`와 `LICENSE-REVIEW.md`를 함께 유지한다.

## 변경 분류

작업 전 변경을 다음 중 하나로 분류한다.

1. `policy`: 법률, 시행령·규칙, 국세청 해석·안내, 세율·공제·경비율 변경
2. `efile`: 전자신고 파일설명서, 서식, 레코드, 인코딩, 오류검증 변경
3. `site`: 공식 웹사이트 URL·구조·게시물 변경
4. `code`: 정책 의미를 바꾸지 않는 리팩터링·성능·개발환경 변경

여러 분류에 걸치면 가장 위험한 `efile > policy > site > code` 순으로 검토한다.

## 필수 유지보수 절차

1. `git status`와 현재 브랜치, 기존 변경을 확인한다.
2. `python -m krtax.maintenance validate`로 규칙·출처 레지스트리·승인 해시를 검사한다.
3. 정책/사이트 감시는 명시적으로 `--online`을 준 경우에만 실행한다. 원문 요구사항이나 고객 데이터를 요청 본문·헤더에 넣지 않는다.
4. 변경 감지는 사실이 아니라 신호다. 페이지 레이아웃·조회수·공지 문구 변경일 수 있으므로 공식 원문과 시행일을 사람이 확인한다.
5. 새 규칙은 기존 연도 파일을 덮어쓰지 말고 귀속연도별 파일로 추가한다. 정정이 필요하면 버전과 근거를 올리고 변경 이유를 기록한다.
6. 세율, 누진공제, 근로소득공제, 경비율, 신고 서식 변경에는 경계값 `-1/0/+1원` 테스트와 전년도 회귀 테스트를 추가한다.
7. 전자신고 스키마는 공식 파일설명서의 출처·버전·해시, 적용 귀속연도, 검토자를 기록하기 전 `reviewed=True`로 두지 않는다.
8. 전체 테스트와 `git diff --check`를 실행한다.
9. 변경 요약 리포트를 제시하고 사용자 승인을 받기 전 커밋·푸시하지 않는다.

## 자동화가 해서는 안 되는 일

- 웹 변경을 근거로 운영 규칙이나 전자신고 스키마를 자동 승격하지 않는다.
- 검색 결과·요약·과거 서식을 최신 공식 규격으로 간주하지 않는다.
- 미지원 사례를 0원, 기본 경비율 또는 전년도 값으로 조용히 대체하지 않는다.
- 실패한 소스 확인을 “변경 없음”으로 기록하지 않는다.
- 공식 변환검증 없이 제출 가능 상태로 표시하지 않는다.

## 근거 기록 기준

정책 변경 문서에는 기관, 문서명, 공개일/개정일, 시행일, 적용 귀속연도, URL 또는 파일 해시, 확인일, 뒷받침하는 필드, 상충 자료를 기록한다. 근거 수준은 `확립`, `유력`, `가설`, `미확인`으로 표시한다.

## 완료 조건

- 오프라인 harness 검증과 단위 테스트가 모두 통과한다.
- 변경된 계산 단계의 골든 케이스가 일치한다.
- 미지원/불명확 사례가 수동검토로 라우팅된다.
- 전자신고 변경은 공식 변환검증 오류 0건을 별도로 확인한다.
- 문서, 규칙 버전, 테스트, 승인 아티팩트 해시가 서로 일치한다.
