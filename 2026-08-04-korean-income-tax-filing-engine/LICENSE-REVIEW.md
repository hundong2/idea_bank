# 라이선스 검토 기록

검토일: 2026-08-04

선택 라이선스: Apache License 2.0

SPDX 식별자: `Apache-2.0`

> 이 기록은 라이선스 선택 이유와 남은 위험을 설명하기 위한 것이며 변호사의 법률의견이 아니다. 라이선스는 법적 분쟁이나 규제 책임이 발생하지 않는다고 보장하지 않는다.

## 선택 이유

Apache-2.0은 Open Source Initiative(OSI)가 승인하고 SPDX가 표준 식별자를 제공하는 널리 사용되는 허용적 오픈소스 라이선스다.

- 제2조: 저작권 사용허락 범위를 명시한다.
- 제3조: 기여자가 허여할 수 있는 범위의 특허 라이선스와 특허소송 시 종료를 명시한다.
- 제4조: 재배포 시 라이선스 제공, 수정 고지, 기존 권리표시 유지 의무를 둔다.
- 제5조: 별도 표시가 없는 기여물을 Apache-2.0 조건으로 제출한 것으로 취급한다.
- 제6조: 상표권을 허여하지 않는다.
- 제7조: `AS IS` 무보증을 규정한다.
- 제8조: 강행법이나 별도 서면 합의가 없는 범위에서 책임을 제한한다.
- 제9조: 재배포자가 추가 보증이나 책임을 부담할 때 다른 기여자를 대신할 수 없도록 한다.

공식 원문은 [Apache Software Foundation](https://www.apache.org/licenses/LICENSE-2.0.txt), 승인 상태는 [OSI](https://opensource.org/license/apache-2.0), 식별자는 [SPDX](https://spdx.org/licenses/Apache-2.0.html)에서 확인했다. 저장소의 `LICENSE`는 공식 영문 원문을 변경하지 않고 수록한다. 번역문은 법적 원문으로 사용하지 않는다.

## 대안과 선택하지 않은 이유

| 대안 | 장점 | 이 프로젝트에서의 판단 |
|---|---|---|
| MIT | 짧고 단순한 허용적 라이선스 | 명시적 특허 허여·종료와 기여 조항이 없어 Apache-2.0보다 권리관계 설명이 적다. |
| BSD-3-Clause | 단순하며 이름을 홍보에 사용하는 것을 제한 | Apache-2.0보다 특허·기여 조항이 덜 구체적이다. |
| GPL/AGPL | 파생물 또는 네트워크 서비스에 강한 공개 의무 | 발주처의 비공개 시스템 결합과 상용 배포 제약이 커질 수 있다. |
| 비공개/상용 라이선스 | 배포·사용자를 계약으로 제한 가능 | 오픈소스가 아니며 별도 계약서와 당사자 특정이 필요하다. |

## 라이선스가 해결하지 않는 위험

- 세액 계산·신고·환급의 정확성 및 세무전문가 책임
- 전자신고 권한, 개인정보 처리, 보안사고와 데이터 보존
- 고의·중과실 등 관할 법률상 제한할 수 없는 책임
- 발주계약, 서비스 이용약관, 개인정보처리방침, SLA 또는 손해배상 한도
- 제3자 코드·데이터·문서의 라이선스와 저작권
- 기여자가 실제로 보유하지 않은 권리나 영업비밀의 유입
- 상표·서비스명 사용권

실제 세무서비스 운영자는 별도의 서비스 이용약관과 개인정보처리방침, 고객 계약의 책임·보증·배상 한도, 전문 검토와 사고 대응 절차를 관할 변호사에게 검토받아야 한다.

## 공개 전 필수 확인

1. 저장소 소유자가 전체 코드·문서에 Apache-2.0을 허여할 권한이 있는지 확인한다.
2. 원 발주자료, 고객정보, 비공개 전자신고 규격과 영업비밀이 포함되지 않았는지 검사한다.
3. 외부 기여는 `CONTRIBUTING.md`의 Developer Certificate of Origin(DCO) 절차를 따른다.
4. 제3자 구성요소가 추가되면 라이선스, 저작권 고지, NOTICE 필요 여부를 기록한다.
5. 저작권자의 정확한 법적 명칭을 확정하면 별도 저작권 고지를 추가한다. 확인되지 않은 개인·법인명을 임의로 기재하지 않는다.
6. Git 저장소 공개 전 별도의 명시적 공개 승인을 받는다.
